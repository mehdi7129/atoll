# Audit complet du 2026-08-12 — v0.16.2

**Trois défauts corrigés, aucune fonction ajoutée.** 700 tests verts (686 + 14),
build Debug sans un warning. Les deux premiers défauts sont des **chemins
destructeurs** sur `~/.claude/settings.json` — le fichier sacré de la règle n° 2.

## Comment cet audit a été mené

Pas de workflow multi-agents cette fois : une passe **solo**, guidée par les
motifs de défaut que les audits précédents ont rendus connus (correctif appliqué
à une partie seulement de ses points d'entrée ; fonction écrite, testée, jamais
appelée ; document de continuité qui dérive). Chaque défaut a été **prouvé par
exécution** — un paquet SPM jetable dépendant d'`AtollCore` par chemin, hors du
dépôt — jamais par simple lecture. Chaque correctif a ensuite été **neutralisé**
pour vérifier que ses tests échouent sans lui.

Couverture honnête : `Bridge/` (1 445 l.) lu intégralement, ainsi que les cinq
éditeurs de `settings.json`, `InteractionCenter`, `PermissionDecision`,
`ProcessInspector`, `BridgeServer`, `RecallJournal`, `ProactiveRecallHook`.
`SessionStore` (1 037 l.), `MemoryIndex` (1 049 l.) et `RetrospectiveRunner`
(710 l.) n'ont été sondés que par recherches ciblées — **pas relus ligne à
ligne**. Un audit multi-agents sur ces trois-là reste à faire.

## Corrigé

### 1. Le correctif de v0.16.1 ne couvrait que 3 des 5 écrivains de settings.json

La v0.16.1 avait corrigé « un `settings.json` de zéro octet écrase la
configuration » dans `HookSettingsEditor`, `SoundHookEditor` et `refreshBackup`.
**`RockstarPermissionsEditor` et `StatusLineEditor` avaient gardé le code
vulnérable**, `guard let data, !data.isEmpty else { return [:] }`, mot pour mot.

Mesuré sur une configuration réaliste :

```
RockstarPermissionsEditor.restore(into: Data(), parked: [...]) → AUCUNE ERREUR
fichier écrit : {"permissions":{"deny":["Bash(rm -rf:*)","Read(./.env)"]}}
hooks GSD : PERDUS · statusLine : PERDUE · env/model : PERDUS · allow : PERDUES
contrôle → SoundHookEditor.restore : refusé ✅   HookSettingsEditor.install : refusé ✅
```

C'est le plus dangereux des cinq, pour une raison qui n'a rien à voir avec la
probabilité : `performRockstarRestore` écrit **puis supprime**
`rockstar-parked-deny.json`. La configuration écrasée n'a alors plus aucune trace
nulle part. (`park`, lui, était sain : il sort en `nil` sans écrire.)
`readSettings()` rend bien `Data()` pour un fichier de 0 octet — le chemin est
complet.

`StatusLineEditor` ajoutait une **perte en cascade** : le fichier lu paraissant
vide, `originalCommand` valait `nil`, donc la statusline de l'utilisateur était
enregistrée comme « aucune » — la désinstallation l'aurait **supprimée** au lieu
de la restituer.

Correctif : la garde `HookSettingsEditor.isBlank` des trois autres, aux deux
`parse` manquants. Neuf tests dans `SettingsBlankFileTests` (le fichier qui
portait déjà ce défaut pour les trois autres), dont **5 échouent** si on retire
la garde.

> **Leçon.** Un correctif de sécurité doit être confronté à la LISTE de ses
> points d'application, par script, pas de mémoire. Le fichier de test v0.16.1
> nommait pourtant `SoundHookEditor` « même défaut, chemin plus dangereux : il
> RETIRE » — le raisonnement était juste, il s'est arrêté un cran trop tôt.

### 2. Le journal du recall comptait ce qu'on espérait envoyer, pas ce qui partait

`ProactiveRecallHook` journalisait `significant.prefix(maxHits)`. Or la
construction du bloc écarte **deux fois** : les extraits vides après nettoyage,
puis tous ceux qui ne tiennent pas sous `maxContextCharacters` (1800). Le
commentaire juste au-dessus nommait pourtant les deux filtres.

Reproduit à `maxHits: 5` avec des extraits pleins (titre et snippet à leur
limite) : le bloc en emporte **4**, le journal en enregistrait **5** — avec 5
couvertures et 5 `keys`, dont une désignant un souvenir que le modèle n'a jamais
lu. Le bloc, lui, annonçait bien « 4 extrait(s) » au modèle : le code savait,
seul le journal se trompait.

**Ce que la mesure sur les vraies données a corrigé.** Sur les **102 passages**
déjà enregistrés (80 injections, 398 extraits), le bloc culmine à **1347
caractères** — jamais dans la zone où la ligne suivante ne rentre plus. **Le cap
n'a donc jamais mordu en usage réel** : les données déjà collectées ne sont pas
corrompues, et le rendez-vous du ~9 septembre garde sa base. Les snippets rendus
par FTS5 sont en pratique bien plus courts que leur limite de 220 caractères.
Le défaut reste réel — le filtre des extraits vides peut mordre à tout moment, et
le cap dès que les snippets s'allongent — mais son ampleur mesurée sur
l'existant est **nulle**, pas « ~20 % » comme l'estimation théorique le laissait
craindre.

Correctif : `ProactiveRecall.injectedBlock` rend le texte **et** les extraits
qu'il contient réellement, depuis la même boucle. `additionalContext` délègue.
Il n'y a plus de second endroit où recompter — la divergence devient impossible
par construction plutôt que corrigée à deux endroits. Le compte remonté à l'îlot
en dérive aussi. Cinq tests, dont **6 assertions qui échouent** si `hits`
redevient `prefix(maxHits)`.

> **Leçon.** Un instrument de décision doit être audité comme du code de
> production : il ne mesure rien s'il mesure une intention. Et le journal
> existait déjà — c'est LUI qui a permis de démentir mon estimation théorique du
> biais. Sans lui, le chiffre de « ~20 % » serait entré dans ce document.

### 3. `SoundCenter` confondait « absent » et « illisible »

`parkUserSoundHooks` et `applyRestore` lisaient `settings.json` avec
`try? Data(contentsOf:)` avant d'écrire : un fichier **présent mais illisible**
(droits, I/O) devenait `nil`, donc « machine neuve ». Mesuré :
`SoundHookEditor.restore(into: nil, parked: [1 hook])` produit un fichier réduit
à `["hooks"]`.

Le helper tient cet invariant depuis toujours (`BridgeCLI.readSettings` : *« ne
jamais confondre absent et illisible, sinon on remplacerait la config par du
vide »*), et `SoundCenter` le tenait déjà **pour son propre fichier de parking**
(`parkingState()` distingue `.none` d'`.unreadable`) : il ne manquait qu'au
fichier de l'utilisateur. Correctif : un `readSettings()` qui laisse remonter
l'erreur. Moins probable que le n° 1 — il faut un settings.json illisible — et
`park` était déjà sain.

  `HookSettingsEditor.managedEventNames`.
- **Dérives documentaires** : tests annoncés 628/644 pour 686 réels (avant ce
