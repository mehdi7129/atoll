## Corrigé (tout est compilé + testé : 620 tests verts, build sans warning)

### Sécurité
- **`AutoAcceptPolicy` — `&` n'était pas un séparateur de segment.**
  `ls & rm -rf ~/Documents` était AUTO-APPROUVÉ (seul `ls` était examiné).
  Idem `git status & git push --force`, qui contournait la garde anti-force-push.
  Corrigé + redirections `2>&1` / `&>` préservées + tests.
- **`AutoAcceptPolicy` — interpréteurs à code en ligne.** `node -e "…rmSync…"`,
  `python3 -c`, `ruby -e`, `awk 'BEGIN{system(…)}'` passaient : la garde `-c` ne
  connaissait que les noms de shells. Jugé désormais par SEGMENT (donc
  `grep -e node` n'est pas confondu avec `node -e`). `python3 script.py` continue
  de passer.
- **Helper : socket `/tmp` non authentifié.** `/private/tmp` est world-writable :
  un autre compte local pouvait préempter `/tmp/atoll-<uid>.sock`, lire tous les
  payloads et répondre `{"behavior":"allow"}`. Contrôle `LOCAL_PEERCRED` ajouté
  (race-free). **Vérifié en vrai** : les événements passent toujours
  (eventCount 9525 → 9527).
- **Skills : les alertes de contenu suspect n'étaient jamais montrées.**
  `flags` (« pipe-to-shell », « base64-blob »…) était calculé, écrit dans
  meta.json, et jamais relu : on approuvait un skill signalé sans voir l'alerte.
  Propagé jusqu'à un bloc « CONTENU SIGNALÉ » dans la fenêtre de revue.

### Perte de données
- **Skills : `approve`/`archiveInstalled`/`uninstallAll` archivaient SEULEMENT
  `SKILL.md` puis supprimaient le DOSSIER entier** — `references/`, `scripts/`
  perdus sans copie, en contradiction avec l'invariant du type. Archivage du
  dossier complet + 2 tests.
- **`mergeParked` dédoublonnait sur la seule commande** : une entrée re-posée
  avec un autre matcher était retirée de settings.json ET jetée du parking →
  perdue. Clé = événement + matcher + JSON complet.
- **`isSoundCommand` ignorait `\n` et le `&` isolé** : un hook
  `afplay done.wav & node notify.js` était parqué en entier — le `node` sautait.
- **`refreshBackup` pouvait écraser le backup « pré-Atoll » avec notre propre
  statusline dedans** (retirer un seul hook à la main suffisait).
- **`atoll-bridge uninstall` ne rendait pas les hooks sonores parqués** — seul
  chemin disponible si l'app est supprimée. Ajouté, même schéma que Rockstar.
- **« Désinstaller les hooks » effaçait tous les skills appris sans un mot.**
  Confirmation ajoutée, qui nomme les skills et dit que réinstaller ne les
  remettra pas.
- **`SoundCenter.reconcile` re-parquait un hook remis à la main** (ou restauré
  par des dotfiles), à chaque lancement. Départagé par la date de
  modification de settings.json.
- **Parking sonore : écriture sur un chemin non résolu** → un
  `~/.claude/settings.json` géré en dotfiles (symlink) était remplacé par un
  fichier ordinaire, dépôt débranché en silence.

### Logique
- **Un seul instantané de flotte vide annonçait toutes les tâches `--bg` comme
  terminées** — définitivement (`notified` idempotent), pendant que l'îlot les
  affichait encore « en cours ». Tolérance alignée sur celle du store (2 tours).
- **L'adoption pouvait voler la session interactive de l'utilisateur** (lancement
  raté + `claude` relancé à la main dans les 3 min). Drapeau `adoptable`.
- **Sessions de worktree tuées puis recréées en boucle** : le filtre `continue`
  sautait l'entrée AVANT la corrélation, donc la session n'entrait jamais dans
  `seen`. Chaque clôture mettait en file une rétrospective payante sur une
  session vivante.
- **Le garde-fou « carte de permission en attente = session vivante » était
  documenté mais absent** de la boucle de retrait par la flotte : la carte
  disparaissait pendant que le helper attendait toujours.
- **Deux `claude -p` payants en parallèle**, trois causes : verrou posé APRÈS
  l'await du condensé ; garde rétrospective↔curation à sens unique ; kill-switch
  sans effet sur un lancement déjà engagé.
- **La curation refusait sec sur quota inconnu/périmé** — exactement le défaut
  que la Phase 12 avait corrigé côté rétrospective (« LA cause du silence »).
- **Les notes d'apprentissage étaient invisibles du recall** dans la config par
  défaut : indexées sans cwd, le filtre « limiter au projet courant » (ON par

- **Quota 5 h périmé toujours affiché** (la pilule annonçait « 5h 60 % » le

- **Deux instances d'Atoll se volaient puis se détruisaient le socket.**
- Journal d'apprentissage : le code de sortie va au journal (`failed(exit 143)`

## Arbitrage rendu — l'îlot au repos (2026-07-27)

Deux intentions du projet s'opposaient, toutes deux écrites dans le code :

- « au repos, l'îlot épouse exactement l'encoche et reste invisible »
  (`IslandGeometry.compactSize`) ;
- « le losange rouge est un indicateur persistant permanent » (`CompactView`).

Sur un écran à encoche et zéro session, la première gagnait par construction :
le HStack des ailes est conditionné à `hasActivity`, donc ni le losange Rockstar
ni le « + » d'un skill proposé n'étaient jamais dessinés. Le losange « au repos »
existait dans `statusGlyph` — inatteignable.

**Décision (demandée par Mehdi) : les deux intentions sont RANGÉES, pas
fusionnées.**

- L'invisibilité au repos **l'emporte** pour tout ce qui est seulement EN
  ATTENTE. Un skill proposé sait attendre : il reste visible dans le menu de la
  barre, et dès qu'une session tourne. Rompre le silence pour une suggestion
  éroderait la propriété qui fait la valeur de l'app — ne rien demander tant
  qu'il ne se passe rien.
- Elle **cède pour Rockstar, et pour lui seul.** Ce mode ne se contente pas
  d'auto-approuver : il SUSPEND les règles `permissions.deny` que l'utilisateur
  a écrites dans son `settings.json` (elles sont parquées dans
  `~/.atoll/rockstar-parked-deny.json`). Une garantie qu'il a posée lui-même est
  levée ; ne rien afficher, c'est le laisser l'oublier. Ici le silence est un
  défaut, pas une qualité.

Mise en œuvre : `NotchViewModel.islandSize(rockstar:)` et le HStack de
`CompactView` prennent `hasActivity || rockstar`. Le drapeau vient de la VUE
(`@AppStorage`), pas du modèle : `InteractionCenter.autonomyLevel` est calculé
depuis UserDefaults, donc invisible à `@Observable` — sans cela l'îlot ne se
redessinerait pas à la bascule du mode.

VÉRIFIÉ : aucune régression avec des sessions présentes (capture — glyphe rouge,
nom de session, quota). Le cas « zéro session » n'est pas capturable sur cette
machine (la session de dev en est une) : c'est le même chemin de rendu avec
`focusSession == nil`, l'aile gauche n'affichant alors que le glyphe.
